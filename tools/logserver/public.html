PetDoor

Opens a pet door when your animal walks up to it, and closes it again once they have gone. No cloud, no app, no subscription — an ESP32 and a Bluetooth beacon on the collar are the whole system.

Door log & analytics → Source on GitHub

What it is

An ESP32 listens continuously for a Bluetooth beacon on your pet's collar. When the beacon has been convincingly close for a moment it pulses an OPEN relay; when it has been convincingly gone for a while it pulses a CLOSE relay. The door's own controller still owns the motor and its travel limits.

The build

A commercial pet door converted by wiring two relay contacts across the controller's existing buttons. The original panel, its buttons and its timer all still work — the conversion adds a second way to press them.

How it works

Four stages, each fixing a different failure mode.

Listen

The radio reports every advertisement, not just the first — roughly two readings a second from the collar beacon.

Filter

A median filter kills multipath spikes, then smoothing removes what is left. It runs twice: fast for opening, slow for closing.

Decide

Two thresholds with a dead band between them, so the door never flaps at the boundary, plus dwell timers in both directions.

Act

A momentary relay pulse — the same as someone pressing the button. The door's own controller runs the motor to its limits.

The log

Every open, close, boot and lost-signal event is recorded on the door itself and optionally uploaded here, signed with a shared key. The dashboard turns that into trip durations, daily rhythm and a beacon battery trend.

The analytics are private. This page is public; the door log and everything derived from it sits behind sign-in, because when a door opens and closes says a great deal about when a house is occupied. The door itself never needs this server — it keeps its own rolling log and works exactly the same with no network at all.
