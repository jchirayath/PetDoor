PetDoor

Opens a pet door when your animal walks up to it, and closes it again once they have gone. No cloud, no app, no subscription — an ESP32 and a Bluetooth beacon on the collar are the whole system.

What it is

An ESP32 listens continuously for a Bluetooth beacon on your pet's collar. When the beacon has been convincingly close for a moment it pulses an OPEN relay; when it has been convincingly gone for a while it pulses a CLOSE relay. The door's own controller still owns the motor and its travel limits.

The build

A commercial pet door converted by wiring two relay contacts across the controller's existing buttons. The original panel, its buttons and its timer all still work — the conversion adds a second way to press them.

How it works

Four stages, each fixing a different failure mode.

Listen

The radio reports every advertisement, not just the first — roughly two readings a second from the collar beacon.

Filter

A median filter kills multipath spikes, then smoothing removes what is left. It runs twice: fast for opening, slow for closing.

Decide

Two thresholds with a dead band between them, so the door never flaps at the boundary, plus dwell timers in both directions.

Act

A momentary relay pulse — the same as someone pressing the button. The door's own controller runs the motor to its limits.

What the collar wears

A Minew BLE beacon — a coin-cell tag about the size of a large button, roughly $12. Not an AirTag, and the reason matters.

Consumer trackers rotate their Bluetooth address on purpose, so there is nothing stable to match against, and they advertise far too slowly — the AirTag's typical gap already exceeds the three seconds after which a reading stops counting as live. A purpose-built beacon does the opposite: a fixed address, printed on the case, ten readings a second.

The log, and the optional dashboard

The door keeps its own log. Every open, close, boot and lost-signal event is recorded in the ESP32's own memory — the last 128, rolling the oldest out so it cannot fill up. Read them over USB whenever you like. That happens on every build, with no network, no server and no setup.

The door — required

An ESP32 and a beacon. Opens and closes the door, keeps its own rolling log, works entirely offline. This is the project.

The dashboard — optional

A separate small program you run yourself, on a Raspberry Pi or any spare machine. The door uploads its log to it over your network, signed with a shared key, and it turns months of events into the charts below.

The dashboard is a single file of stdlib Python and a SQLite database. Nothing is hosted for you and nothing phones home — the address it uploads to is one you set, pointing at a machine you own. Leave it unset and the door never opens a network connection at all.

What it adds: trip durations, daily rhythm, trips per day, and a beacon battery trend that warns you weeks before the cell dies.

The real analytics are private. This page and the sample are public; the actual door log sits behind sign-in, because when a door opens and closes says a great deal about when a house is occupied and when it is empty. The door never needs this server at all — it keeps its own rolling log and behaves identically with no network.

Worth knowing before you build it

The honest limits, stated up front.

It is not a lock

Bluetooth advertisements are unauthenticated. The door opens for anything broadcasting your beacon's address, and reading that address takes a free phone app. Fine against weather, rodents and the neighbour's cat. Not a security barrier.

The animal must wear it

No beacon, no door. That rules out anything that will not keep a collar on, and it means a flat cell stops the door opening — though it fails safe, closed, never on top of an animal.

You are wiring a motor

The door's own controller keeps its limits and current protection; this only presses its buttons. But you are still working on a door an animal walks through. The safety guide is not optional reading.
